## Architecture decision

Separate *live in-process event fan-out* from *durable event persistence and replay*. The RunEventBus maintains run-scoped subscriptions, idempotent unsubscribe and exception containment; PersistenceRepository persists events and publishes through an explicitly injected bus. The application composition creates the bus alongside the SQLite repository, and existing tests inject isolated buses alongside in-memory databases.

The repository temporarily preserves the existing subscribeRunEvents method as a compatibility facade. Durable listRunEventsAfter and the atomic write transaction remain repository responsibilities; a later route extraction can inject the bus and persistence port separately. This staged split avoids changing Last-Event-ID replay, server response closure, event ordering, or authorization while introducing the explicit seam.
